## What reaches the decision

Per DSH's pipeline documentation, every tool registered through the tool registry passes `tools/pre-execute` and then the guards before it runs. That covers the native tools below, each sub-call made by a Code Mode `run_code` program (each is gated separately), and tools that plugins register at runtime (MCP servers, dynamic packages). The forwarder plugin (item B2) sits at both points, so a call that reaches the registry reaches Icarus's decision. A tool that is not in the table is unknown and is denied.

## What does not reach the decision, or is not scoped by it

These are gaps, not covered ground. Each is either denied by default or reported.

1. Effects a permitted tool has that its arguments do not show. Shell and terminal tools are denied by default; if the owner ever allows one, its command string is the only evidence and what it touches is not scoped.
2. Anything that does not go through the tool registry: a plugin acting directly, actions the human takes in the DSH interface, and effects that arrive later from something a call started (background jobs, schedules, goals). The tools that start them are denied by default.
3. Subagent and workflow children may run on other model routes, which would not pass through the model slot. Their tool calls still reach a global guard, but carry no call id that Icarus minted, so they would be denied as unproposed. That holds only if the forwarder is loaded and its guard is global. The tools that start children are denied by default.
4. Tools that appear at runtime (MCP servers, dynamically defined packages) have names the table has never seen, so they are denied. The dynamic-package tools themselves are denied and escalated to the owner as a security matter.
5. Symlinks and junctions. The path mapper is lexical: a link inside the workdir that points outside it is not detected here. Only the file snapshot check (B5) could notice a resulting change.
6. Path forms. Parent traversal, drive-relative paths, alternate data streams, UNC paths, Windows device names, trailing dots and spaces, and anything with `~`, `%` or `$` are refused. That also refuses legitimate names that contain those characters.
7. The workdir root itself cannot be named, because the kernel refuses `.`. A tool cannot list or search the root directory in one call.
8. The `pattern` argument of `glob` and `grep` is not path-checked; only their `path` argument is.
9. A DSH started without the forwarder has only its own policy. Item B3 verifies the configuration before Icarus claims control, and item B10 tests this case on purpose.
