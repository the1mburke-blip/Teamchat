# ICARUS continuous learning

## ICARUS execution contract

Use the active workspace's `learned.md` and the existing Harness read/write/edit tools. Follow their normal approval and workspace boundaries. This skill does not change identity, permissions, or credentials.

1. Read current learned memory before relying on it. A supplied snapshot may be stale.
2. Identify durable new knowledge, owner preferences, corrected assumptions, or a tested procedure from this task/chat. Do not invent lessons to fill a calendar day.
3. Append a dated entry with provenance, evidence and status: owner-stated, observed, verified, or hypothesis. Read the current complete file before a write; retain its entire existing text and append the new entry. A native edit must retain the matched final text and extend it. The enabled observer rejects write/edit operations that truncate this history. Correct contradictions with appended, attributed corrections. Never store secrets, authentication values, or whole private conversations.
4. Read the saved file back. Only say a lesson persists when the actual saved entry is present. If writing failed, report the failure precisely.
5. When a supported procedure changed, update the relevant skill and verify its native catalogue/body readback. Documents describe procedures; available tools still determine executable capabilities.
6. Keep `identity.md` and `inherited.md` immutable. For a generational handoff, create a dated, attributed checkpoint with source hashes and evidence references; never overwrite ancestors or represent a checkpoint as model training.

The local learning observer journals turn checkpoints and successful native file readbacks. A journal event alone does not certify knowledge truth or guarantee that the model saved a lesson. No additional model requests or scheduled background reviews are needed.
