## Architecture and threat boundary

Agents execute. Icarus judges. Skills are procedure only, never authority. `Skills.gs` embeds one repository seed; `skills/repeated-task-actions.json` is its reviewable representation and a deterministic test proves byte-equivalent data. No install/update/create/edit API, database, scheduler, dependency tree, runtime import, shell preprocessing, eval or credential capture is added. Trusted server code writers/admins remain trusted, as in PR63; this is not an OS sandbox.

`skillsList_()` returns only bounded name/description/revision metadata, never instructions/hash/provenance. `skillView_(name[,revision,hash])` resolves exactly one simple name, checks bounds and a full SHA256 over canonical JSON `{name,description,revision,instructions,provenance}`, and optionally enforces expected revision/hash. Registry max10 entries; each name<=64, revision<=32, description<=240, instructions<=6000, provenance JSON<=1200 characters; duplicates, unknown fields, traversal-like names and corrupted hashes deny. Returned data is fresh, caller mutation does not mutate the registry. Hashes prove integrity relative to trusted source, not safety or authority.

One catalogue-only Gemini selection uses `select_procedural_skill(name,revision)` with its own signed `:skill-selection` permit and existing provider transport/capability/model/zero-spend guards. It chooses one known revision or empty name+revision for none; no model hash/content/authority fields are accepted. Trusted host derives/persists the name/revision/hash and original-objective hash in the existing task row with readback. Successful selection is not repeated on auth/reasoning resume. A capacity response requires explicit existing resume; no automatic provider retry. Crash after selection transport but before durable selection stays fail-closed under consumed permit.

The existing execution reasoning receives the compact catalogue plus at most one explicitly selected body. It still calls only `execute_authorized_task`. All catalogue-exposed replies (including no selected body) and cached selected-or-none plans must return the exact original objective unchanged; native operation validation still binds original service/target/range/payload. No second provider or agent architecture exists. A task may now have one additional bounded provider request for selection; this repository task invokes zero live requests. Future deployment still requires actual free-billing/quota evidence, as PR63 requires.

Selected fields `skillName`, `skillRevision`, `skillHash` join the strict signed spec allowlist. They bind applicable reasoning/native/Composio/discovery permits. Host task binding, current source content and revision must match at admission/consumption. Missing/partial/replaced bindings deny. Stale READY permits are revoked before transport. Cached reasoning and PENDING_AUTH/EXECUTING/VERIFYING resume revalidate the same selection rather than silently reselecting a new revision. Selection never controls authenticated executor, objective, tool/service, operation, target, scopes, route, EUR0 budget, write gate, evidence contract, verifier identity or PASS. Existing owner-verdict seam remains authoritative.
