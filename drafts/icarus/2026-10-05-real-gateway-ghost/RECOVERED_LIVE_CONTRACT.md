## 2. Pair operation
POST body fields:
- op = "pair"
- deviceId
- pairingCode
- clientVersion
- googleIdToken only when present

Response envelope:
- ok: boolean
- error: string on failure
- data.deviceId
- data.token
- data.runtimeVersion
- data.environment

The token is stored locally as a secret by the Android app. The server archive hashes the token in DEVICE_REGISTRY; plaintext is returned only to the client during pairing.

## 3. Submit operation
POST body fields:
- op = "submit"
- deviceId
- token
- clientTaskId = UUID generated by Android
- text = user task

Response envelope:
- ok: boolean
- error: string on failure
- data = task snapshot

Task snapshot fields consumed by Android:
- task_id
- status
- objective
- evidence_ref

## 4. Status operation
POST body fields:
- op = "status"
- deviceId
- token
- taskId

Response uses the same {ok,data} envelope and task snapshot fields:
- task_id
- status
- objective
- evidence_ref

## 5. Resume and runtime server operations
Archived Apps Script doPost also accepts:
- resume: authenticated body with op="resume" and taskId
- runtime: authenticated body with op="runtime"

The archived Android client implements runtime and status directly; no claim is made here that the archived client implements resume.
